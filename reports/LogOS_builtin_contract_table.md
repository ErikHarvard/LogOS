Vocabulary used in cells:

* Types: `STR` (binary-safe string value), `INT` (native integer value), `DEC` (an integer **spelled as a decimal string**, the VM syscall convention), `any`, `"!"` (argument evaluated for ordering but ignored), `CLO` (closure), `BOOL` (Church boolean closure `la t. la f. …`).
* `halt "…" rc1` = diagnostic on stderr + exit 1. `-errno` = returns the negative errno as a `DEC` string. `""` = returns the empty string. `silent` = wrong/degraded result, exit code 0. `SIGSEGV`/`SIGFPE` = crash (rc 139/136). `ok` = matches the row's contract column exactly. `—` = the engine has no such builtin (host/eval/RUN_*: name is unbound → that engine's unbound-variable halt, see §2 row E1; native3: compile-time `native_codegen3: unbound name: <n>` :327).
* eval.la / RUN_BYTES / RUN_SM **forward** every builtin to the host builtin of the same name after unwrapping; their own contribution is the unwrap coercion, so a cell says `fwd` when behaviour = host's, plus the coercion caveat (§1 legend `U`).

Legend `U` (the unwrap coercions, applied on the three self-hosted engines before forwarding):
* `U-str`: `UNWRAP_STR` turns an INT into its decimal string (eval.la:227, bytecode.la:338) — so a string builtin given an INT does **not** halt as the host does; it runs on the decimal. On eval.la a CLO/BI/PA arg halts `"eval: expected a string, got a closure|builtin|partial"` rc1 (:227); on RUN_BYTES/RUN_SM a CLO/BI/PA arg becomes `""` **silently** (bytecode.la:338).
* `U-int`: `UNWRAP_INT` turns a STR/CLO/BI/PA into `0` **silently** on all three (eval.la:228, bytecode.la:339) — so `add("x")(1)` = 1, no halt.

## 2. DISAGREEMENTS

Numbered, with the precise difference and the `file:line` on each side. "Known" marks items already recorded in CLAUDE.md / FREEZE_* notes.

1. **`typeof` is host-only.** `tiny_host.c:531,861–869` defines it; no entry in `eval.la:251–277`, `bytecode.la:341–380`, `secd.asm` name chain (474–805), or `native_codegen3.la:305–312`. On every other engine it is an unbound variable (E1). *(known)*
2. **`chr` / `ord` / `write_exec` / `error` are absent from eval.la, RUN_BYTES and RUN_SM** (`eval.la:251–277`, `bytecode.la:341–380` lack them) while present on host (`:505–506,:534`), VM (ids 8,9,10,30) and native3 (`:305–306`). *(known)*
3. **`str_at` is absent from native3** (`native_codegen3.la:305–306,312`) but present on host (`:514`), eval.la (`:261`), bytecode (`:351`), VM (id 66, `secd.asm:674`).
4. **`chr`/`ord`/`str_len` return decimal STRINGS, not INTs, on every engine** (host `:817,:827,:808`; VM `push_dec`-style `:1600–1678`; native3 `rt_int_to_str_raw` `:1137,:1151`) — while `int_to_str`/`str_to_int` are the INT bridge. Not a cross-engine disagreement, but a contract oddity every table reader trips on. *(known)*
5. **`chr` parse leniency differs three ways.** Host uses `strtol` (prefix parse: `"12x"`→12, `"abc"`→0, `tiny_host.c:805`); VM folds every byte through `(c-'0')` with no validation (`secd.asm:1574–1583`: `"abc"` → 97·100+98·10+99 = 10 779 → halts `chr out of range`; `"12x"` → 1200+72−48 → 1224 → halt; `"1 "` → 10−48+… garbage in range); native3 does the same unvalidated fold (`native_codegen3_rt.asm:1164–1172`). Only `str_to_int` was made strict; `chr` was not.
6. **VM integer builtins are unchecked** (`secd.asm:3365–3447`: `int_to_str`, `add`…`int_eq`, `band`…`bnot` read the payload with no tag test), so `add("x")(1)` silently uses the descriptor pointer as the integer and `int_to_str("x")` prints a pointer, rc 0. Host halts (`tiny_host.c:694,:831,:836,:842`); native3 halts via `chk_int2`/inline tag check (`rt.asm:1650–1655,:572,:1710`). *(known)*
7. **eval.la / RUN_BYTES / RUN_SM silently coerce for int builtins**: `UNWRAP_INT` maps STR/CLO/BI/PA → 0 (`eval.la:228`, `bytecode.la:339`), so `add("x")(1)` = 1, `str_at(s)("2")` = byte 0, no halt — a third behaviour distinct from both host (halt) and VM (garbage).
8. **eval.la / RUN_BYTES / RUN_SM silently coerce INT → decimal for string builtins**: `UNWRAP_STR` (`eval.la:227`, `bytecode.la:338`) so `concat(5)("x")` = `"5x"`, `str_len(5)` = `"1"`, `read_file(5)` tries to open `"5"`; host halts with `<b>: … is not a string` (`tiny_host.c:758,:777,:782,:787,:792,:797,:824`); VM and native3 halt (`secd.asm .strtype`, `rt_not_string`).
9. **CLO/BI/PA given to a string builtin** — three behaviours: eval.la halts `eval: expected a string, got a closure|builtin|partial` rc1 (`eval.la:227`); RUN_BYTES/RUN_SM substitute `""` silently (`bytecode.la:338`); host/VM/native3 halt with their `not a string` messages.
10. **`print` of a non-string/non-int**: host prints `print: argument is not a string or integer` to stderr and **continues** (rc 0) (`tiny_host.c:746`); native3 same (`rt.asm:349–356`); VM **halts** `secd: argument is not a string` rc1 (`secd.asm:1297–1300`); eval.la halts via `UNWRAP_STR` (`eval.la:287`); RUN_BYTES/RUN_SM print an **empty line** silently (`bytecode.la:417`). *(known: "print non-string")*
11. **`read_file` on open failure**: host halts `read_file: cannot open '<p>': …` rc1 (`tiny_host.c:605`); native3 halts `native: read_file: cannot open file` rc1 (`rt.asm:1453–1459`); VM **returns `""`** silently (`secd.asm:1463–1464,:1486–1495`). *(known)*
12. **`read_file` on a non-seekable file**: host halts (`tiny_host.c:613`), native3 halts (`rt.asm:1407–1408,:1460`); VM has no check (single 64 MiB `read`, `secd.asm:1467–1471`) — returns whatever one read returns.
13. **`write_file` / `write_exec` on open failure**: host halts `write_file: cannot open` rc1 (`tiny_host.c:629,:641`); native3 halts `native: write_file failed` / `native: write_exec failed` rc1 (`rt.asm:1357–1367,:1280–1290`); VM **silently returns the content** (`secd.asm:2195–2196 .wf_done`, `:2238–2239 .we_done`) — the caller cannot tell the write failed.
14. **`write_file` path-length**: host unbounded (`fopen`), VM ≥4096 → `secd: path too long` (`secd.asm:2177–2178`), native3 ≥4095 → `native: write_file path too long` (`rt.asm:1307–1308`, note `jae` so 4095 itself is rejected; VM uses `ja` so 4095 is accepted). Same off-by-one between `secd.asm:1445` (`ja 4095`) and `rt.asm:1382` (`jae 4095`) for `read_file`, and `rt.asm:1226` vs `secd.asm:2220` for `write_exec`. native3 also reuses the `write_exec path too long` message for `read_file` (`rt.asm:1449`).
15. **`copy_self` target name & failure**: host `new_logos_gen{N+1}_pid{P}.bin`, halts with `perror` rc1 on any open/write failure (`tiny_host.c:576–596`); VM fixed `new_logos_secd.bin`, **any failure silently returns the path** (`secd.asm:1503–1504,:1511–1512`); native3 fixed `new_logos_native.bin`, open failures silent (`rt.asm:1486,:1494`), write failure loud (`:1544`). The lineage/generation encoding exists only on the host.
16. **`copy_self` argument**: host evaluates and ignores (`tiny_host.c:750`); eval.la substitutes the literal `"self"` (`eval.la:293`); RUN_* pass `UNWRAP_STR(val)` (`bytecode.la:418`); VM/native3 never touch it. Observably equal, but the meta engines re-enter the host builtin with a different argument.
17. **`error` with a non-STR argument**: host prints INT as decimal, other as `(non-string error message)`, exit 1 (`tiny_host.c:872–874`); VM has **no tag check** and derefs an INT payload as a descriptor → **SIGSEGV** (`secd.asm:2479–2480`); native3 likewise (`rt.asm:1189–1191`). The one string builtin on the VM the "not a string" audit missed.
18. **`div` by zero diagnostic**: host `div: division by zero` rc1 (`tiny_host.c:704`); native3 `native: div: division by zero` rc1 (`rt.asm:1616`); VM **exit 1 with no message** (`secd.asm:3435–3438`). Same for `mod` (`:727` / `:1625` / `:3391`).
19. **`div`/`mod` on LONG_MIN / −1**: host halts `div: overflow (LONG_MIN / -1)` and returns 0 for mod (`tiny_host.c:705,:728`); native3 halts (with the misleading `division by zero` text, `rt.asm:389–393`) and returns 0 for mod (`:406–412`); VM **SIGFPE** for both (`secd.asm:3382–3396`, bare `idiv`).
20. **Apply a non-function**: host halts rc1 with a message (`tiny_host.c:913`); eval.la halts rc1 (`eval.la:413,:431`); VM halts rc1 (`secd.asm:1046,:3527`); RUN_BYTES and RUN_SM **do not halt** — they produce a `VAL_STR("vm: cannot apply …")`/`"sm: cannot apply …"` value and continue (`bytecode.la:488,:492,:593,:597`); native3 **exits 70 silently** (`rt.asm:286–289`).
21. **Unbound variable message carries the name everywhere except the VM** (`secd.asm:3517` prints `secd: unbound variable` only) and native3 catches it at **compile time** (`native_codegen3.la:327`) rather than at run time.
22. **Builtins as first-class values / partial application**: host, eval.la, RUN_*, VM all allow `concat` unapplied and `concat(a)` partials (`tiny_host.c:895,:907`; `secd.asm:1006,:1211`); native3 rejects at compile time (`native_codegen3.la:737`) and requires saturated `f(a)`, `f(a)(b)`, `f(a)(b)(c)` shapes (`:705–723`).
23. **Type-check timing for curried builtins on the VM**: host checks the first argument at the first application (`tiny_host.c:777,:792,:831`); VM builds the partial unchecked (`.mkpa` `:1076–1090`) and checks **both** tags only at the second application (`secd.asm:2077–2080,:2130–2133,:2170–2173`); native3 checks both at the single saturated call. A program that builds `concat(5)` and never applies it halts on host, runs on VM.
24. **`str_at` bad-index diagnostic on VM** is `secd: argument is not a string` (`secd.asm:1360–1361`) where host says `str_at: index is not an integer` (`tiny_host.c:686`). Host does check arg types; VM message is misleading.
25. **VM `send`/`recv` vs native3 `send`/`recv` are different builtins under the same names**: VM `send(fd)(data)` → `sendto` bytes/-errno (`secd.asm:2730`), `recv(fd)(max)` → `recvfrom` (`:2749`); native3 `send(chan INT)(msg STR)` → returns msg via SYS_SEND 0x300 (`rt.asm:2060`), `recv(chan INT)` is **unary** (`native_codegen3.la:305`, `rt.asm:2073`), 256-byte cap, no tag checks. A `logosipc.la` program cannot mean the same thing on both.
26. **VM syscall builtins take integers as DEC strings; native3 metal builtins take INT values.** `open/close/write/read/…` (`secd.asm` `desc_atoi` `:140–168`, lenient: any non-digit folded as `(c-'0')`) vs `peek/poke/inb/outb/fill/memcpy` (`rt.asm` tag 4 checks). Two incompatible int-crossing conventions; `poll`'s fd list additionally skips stray bytes silently (`secd.asm:3247–3249`).
27. **VM failure-return conventions are not uniform**: most syscalls return `-errno` (`push_dec`); `pipe` and `clock_gettime` return **`"-1"`** (`secd.asm:2522–2524,:2562–2564`); `read`/`recv`/`random` return **`""`** on error (`:2589–2590,:2774–2775,:2839–2840`) — indistinguishable from EOF/zero-length; `execve`/`execv` return `-errno` only on failure; `waitpid` returns `WEXITSTATUS`, not the raw status (`:2415–2417`), though CLAUDE.md says "exit status".
28. **`str_to_int` strictness is aligned host/VM/native3** (`tiny_host.c:855–858`, `secd.asm:3341–3357`, `rt.asm:620–635`) but eval.la/RUN_* reach it through `UNWRAP_STR`, so `str_to_int(5)` on those engines silently round-trips to 5 while the host halts `str_to_int: argument is not a string` (`tiny_host.c:854`).
29. **Resource-guard exit codes**: VM guards exit 1 (`secd.asm:3477–3600`); native3 `rt_stack_overflow` exits **134** (`rt.asm:1121`); host C-stack guard exits 1.
30. **`yield` with no runnable task exits 0 silently** (`rt.asm:1991–1994`) — the only builtin that terminates the process with rc 0 without a message; on all other engines program termination goes through `MAIN` returning.
31. **`present`/`drm_mode` failure diagnostics are VM-only strings** (`secd: drm <call> failed: <rc>`, `secd: present before drm_mode`, `secd.asm:1988–2075`); no other engine has the builtin (VM-only by design, not a divergence, listed for completeness).
32. **Name table vs dispatch drift guard (VM)**: `.apply_bi` (`secd.asm:1075–1210`) and `.apply_pa` (`:1222–1293`) both fall through to `.halt` (**silent exit 0**, `:3472–3475`) for an id with no handler. Every id 0–66 is currently routed, so unreachable — but a future id added to the name chain without a dispatch line would fail silently.
33. **RUN_BYTES/RUN_SM "unknown builtin" fallthrough is a silent string** (`VAL_STR("ERROR: unknown builtin <n>")`, `bytecode.la:398,:413`) whereas eval.la's is `error(...)` rc1 (`eval.la:334,:364`). Unreachable today (every `IS_BI_NAME` name is dispatched) but the two self-hosted engines chose opposite disciplines.
